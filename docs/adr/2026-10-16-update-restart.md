# 安装后重启窗口，保留项目

> 历史方案：此文记录已完成的 v2.0.41 实装验证。后续按用户选择改为完整更新（默认下次启动安装、立即安装前停止清单、更新后恢复项目），现行设计见 [完整更新流程](2026-10-16-update-transaction.md)。下面的“只重启窗口、保留旧后台”不再是新代码的更新策略。

## 用户流程

安装成功显示“新版已安装，重启 RunDock 后生效”，提供“立即重启”和“稍后重启”。稍后仍可从侧栏的安装完成入口回来。点击重启后禁止重复点击和关闭更新面板；准备失败恢复可重试状态，保留旧窗口和项目。

Windows 安装器返回 3010 时保留“需要重启电脑”的提示，不提供仅重启窗口即可完成更新的错误承诺，也不会自动重启电脑。

## 实现与边界

- 安装结果及目标版本保存在原生更新会话中。重启命令不接收前端提供的路径，不允许未安装就调用。
- 从当前安装目录固定寻找 `launcher-platform.exe`，避免重启安装过程中改名保存的旧映像。
- 新进程先核对自身编译版本与安装目标版本一致，取得旧进程句柄后，通过 Windows 事件确认准备就绪。
- 旧窗口收到确认才退出。新进程等待旧进程句柄退出后，才进入 Tauri 单实例初始化，避免只是唤回旧窗口。
- 准备失败仅终止新建的替换进程，不终止旧窗口、后台或项目。
- 重启不调用停止/退出后台接口。原后台继续持有 ConPTY、项目进程及日志，新窗口沿用原有后台复用机制。
- 因此这是**桌面窗口切换到新版**。为保证项目不中断，已运行的后台进程不会同时切换成新二进制；后台代码要等其正常退出后下次启动才更新。

### 实装发现的 Windows 版本缓存问题

运行中安装会将旧 EXE 改名并把新版写入正式路径。Windows 的版本资源 API 在旧进程内按原路径读取时，可能仍返回已加载映像的旧版本，导致“已是最新”的误判。新增读取磁盘安装版本的私有临时快照，读取后清理；外部安装也能进入“已安装，待重启”状态，不需要重复下载或安装。

`scripts/tests/verify-installed-version.mjs` 创建带版本资源的真实 Windows 进程，在运行中替换其正式文件：旧读取方式实测返回 2.0.39 / 2.0.39，修复后返回 2.0.39 / 2.0.40。测试结果保存在 `production-installed-version-final.log`。生产 v2.0.40 → v2.0.41 的按钮验收再次验证了该修复。

保留项目运行也意味着保留当前后台进程；本次“立即重启”仅更新桌面窗口，后台在正常退出后下次启动才载入新版。GitHub 下载交付链路不在此次本地安装验收范围内。
