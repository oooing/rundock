# RunDock 构建与交付开发计划

状态：实现与本地验收完成。范围：本地构建、持久保存、GitHub Release 交付、取消与恢复；保留现有云端目标。

## 业务契约

- 构建位置、发布目的地、上线检查分别配置和显示。
- 发布使用冻结提交、版本、配置和说明。上传恢复不依赖当前 HEAD 或临时候选。
- 每个版本组/Tag 是一个发布批次；同批次全部必需文件验证完成才公开。
- 文件以任务为单位复制、哈希验证、原子封存。重试不得修改封存清单。
- 同名同内容跳过；同名不同内容、Tag 提交不一致、未知草稿均阻断。已公开文件不覆盖。
- 网络请求返回不确定时先查询实际状态；上传以文件为恢复单位。
- 第一版不协调同 Tag 的本地和云端混合产物，不提供跨机器分布式锁，不承诺编译进程断点恢复。
- GitHub 写入由后台发布器执行；账号引用只包含身份，不包含 token。项目构建进程不获取发布凭证。
- 本地工作流检查无法证明远端已更新：正式交付前必须核查远端工作流。检测到重复构建入口则阻断。

## 领域与数据流

配置边界 releaseconfig → 冻结 executionPlan → publisher 编排 → 产物封存/交付 → store 持久化 → API 视图。
GitHub 协议对象只留在交付实现内部。UI 不接触凭证或执行计划内部字段。
继续复用版本组、候选代码、Git 提交、目标状态、日志、错误复制；新模块保持少于 500 行。
拆分本次涉及的 publisher 大文件；前端抽出发布状态和交付设置，避免继续增加大组件职责。

## 开发顺序

1. [x] 固定失败契约和端到端验收入口，记录现有未提交改动。
2. [x] 配置：每步超时、必需产物、验证命令、GitHub 目的地与账号、上线检查。
3. [x] 产物封存：文件复制、哈希、清单、持久记录、恢复校验。
4. [x] GitHub：身份/仓库/Tag/工作流预检、草稿、文件核验、发布、冲突与响应丢失恢复。
5. [x] 编排：本地发布校验、整批完成、进程树取消、跨进程占用、启动恢复。
6. [x] 前端：构建/交付独立选择，构建/发布/同步结果，取消、重试、错误复制。
7. [x] 项目接入：RunDock 自身配置和外部项目接入验收；专项迁移包归外部项目，不发布真实新版本。
8. [x] 结束时执行端到端验收与构建，保留脱敏 JSON 报告和复现命令。

## 先于实现固定的失败清单

环境工具缺失或版本不符；构建/验证命令非零、超时、取消；子进程残留；源码被构建修改；
产物不存在、空文件、重复名称、宽泛规则包含旧包、缺签名、错误证书或包内版本；路径穿越/链接；
复制中断、磁盘不足、清单损坏、封存后文件修改；
上传前断网、上传中断、响应丢失、凭证失效、账号切换、限流；
同 Tag 异提交、同名异内容、未知草稿、缺少远端摘要；
正式发布响应丢失；重启丢失候选；工作区 HEAD 前进；重复点击/多进程争用；
本地发布触发第二次云端构建；同步返回 200 但仍是旧版本。
云端显式调用的补充失败契约：请求被明确拒绝时允许修复后重发；响应丢失且任务暂不可见时仅查询，
重启不得依赖旧候选，发现同任务后不再提交；监控必须同时匹配冻结提交、Tag、工作流和任务标记。

## 验收机制

只新增端到端验收，不补写实现镜像式单元测试。用真实 Git、SQLite、命令进程和 HTTP API，
在外部 GitHub 边界注入可重复的故障。模拟边界证据与真实服务证据分开。
覆盖：正常交付、按文件恢复、重启、重复请求、缺必需文件、内容冲突、取消、HEAD 前进、
未知草稿、成功响应丢失、同步状态独立。报告记录构建次数、上传次数、产物哈希和阶段结果。
开发期间只做格式/编译检查；完整验收在实现结束后执行。

## 迁移和回滚

保留现有 schemaVersion=1 配置契约，增加可选字段；旧配置继续原行为。
新增数据库表使用幂等 DDL，由 sidecar 启动迁移；本项目没有 bun precheck/build:web/db:* 脚本。
不回填旧产物为“已封存”：旧记录没有可信文件快照。
回滚应用前保留数据库与产物目录；旧程序不执行新增交付任务。远端公开版本不会被自动撤销。
Tag 中的发布计划与工作流是跨系统契约，迁移必须保持旧云端入口可用，不能用内部 shim 隐藏变化。
