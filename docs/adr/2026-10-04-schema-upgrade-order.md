# 旧库字段与派生索引的初始化顺序

## 目标与边界

修复 v2.0.22 云端构建暴露的旧库启动失败，保留项目、发布偏好和历史记录。
只调整 store 的数据库初始化依赖；不更改 HTTP 协议、版本号、正式版数据或发布身份。

## 编码前失败清单

- 旧 release_runs 缺 execution_plan_json，009 的索引先于补列执行，启动失败。
- 直接把 ensureSchema 移到所有 SQL 前面：全新数据库尚无表，同样失败。
- 删除索引或仅修改测试样本：重复构建请求失去持久幂等保护，旧库缺陷仍在。
- 重复启动报重复列/索引错误，或覆盖已有计划、偏好、历史与产物。
- 升级后只测健康接口，没有实际验证发布历史、构建、下载和重试。
- 验收误用用户数据库或关闭当前测试端及其托管项目。

## 决策

数据库创建脚本先建立表及不依赖演进字段的基础索引，ensureSchema 补齐旧表字段，
最后建立依赖演进字段的派生索引。idx_local_build_request 从 009 的 SQL 移到
store 初始化的最后阶段；不保留两份建索引逻辑，也不删除已存在的索引。
三个阶段均幂等，失败时关闭数据库并返回具体阶段错误，下一次启动可继续。
依赖新增/补齐字段的后续索引也必须放在该阶段，不能提前引用字段。

这不是 schema_version 框架改造：本次只有一个真实的派生索引用例。
已升级数据库保留既有索引，新增唯一约束不改变；代码回滚不删数据。
DDL 不搬迁存量记录。若未来迁移不能幂等重放，应另立事务/版本化迁移 ADR。

## 验收

先添加 scripts/acceptance/schema-upgrade.mjs，再改生产代码。它使用独立数据目录、
真实 sidecar 进程、HTTP、SQLite 和真实 Node 构建/产物下载；不启动用户项目或访问 GitHub。
覆盖全新库、缺字段旧库、已有索引库、重复启动、旧记录不变、数据库唯一约束、
HTTP 重复构建请求（包括重启后）与产物哈希。结束保留 JSON 报告、日志、库和二进制哈希。
云端已有失败测试必须恢复通过，完整本地打包在最终验收阶段执行。
