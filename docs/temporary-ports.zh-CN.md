# 临时换空闲端口并启动

当原端口被其他项目占用或被系统保留时，端口处理弹窗可提供非破坏性的临时启动方案。新端口仅用于本次运行；不修改项目文件、已保存的启动参数、环境变量、端口提示或健康地址，也不停止原占用程序。卡片显示本次端口；普通停止后再启动仍使用原配置。

## 支持边界

第一版仅支持**明确声明兼容的单服务 Vite npm 入口**。不能仅根据项目使用 Vite/Node 就推断接口可以随端口变化。未适配的启动方式、工作区/包装脚本、多命令、前置/后置脚本、固定登录回调/跨域配置，以及未声明兼容的接口，均不开放临时启动按钮，并显示原因。

项目维护者确认接口使用同源相对路径，或项目内代理及校验会跟随实际监听端口后，可以在 `package.json` 中提供以下声明（RunDock 不会代用户自动添加）：

```json
{
  "scripts": { "dev": "vite --config vite.config.ts" },
  "rundock": {
    "temporaryPort": {
      "version": 1,
      "adapter": "vite",
      "script": "dev",
      "port": 3000,
      "host": "127.0.0.1",
      "interfaces": "same-origin"
    }
  }
}
```

声明的端口必须是此入口的正常监听端口，Vite 配置也应使用该端口与回环地址。当前卡片应执行 `npm.cmd run dev`，工作目录应为此 `package.json` 所在目录。首版不接受脚本内已有 `--port`/`--host` 参数，避免重复参数造成歧义。不能把声明用于会另起后端且后端端口仍冲突的启动脚本，也不能用它绕过跨域、安全校验或接口改造。

临时启动在**复制的运行配置**上追加 `-- --port <临时端口> --host 127.0.0.1 --strictPort`。已配置的同端口健康检查会在内存中同步更新，服务发现和打开地址使用本次实际服务。不会更改业务接口、自动编辑跨域白名单或登录回调。

## 交互与安全

- 用户看到原端口、计划使用的新端口和“仅本次生效”的说明后，主动点击“临时换空闲端口并启动”。
- 方案 60 秒有效、单次使用，并绑定项目配置、入口脚本内容和请求来源。方案过期或配置变化需要重新查看。
- 候选端口由操作系统分配，执行前复核。因应用必须自己绑定端口，检查与启动之间仍有竞态；`--strictPort` 禁止悄悄换到别的端口，失败时不停止任何其他程序。检查服务健康不代表所有业务功能已测试通过。
- 更换网页端口会产生不同浏览器来源；设置/收藏可能位于独立本地存储中，原端口的数据不会删除。
- 原有“关闭占用程序并启动”是独立操作，仍需明确确认；临时启动路径不会调用它。

## 验证

Go 测试覆盖声明识别、配置深拷贝与健康地址同步、绑定判断、单次确认和失效方案。隔离验收使用独立数据目录与临时项目，验证 A 不停、B 在新端口运行、原配置和文件字节不变、同源接口可访问、停止后普通启动恢复原端口，以及候选端口被抢占/不支持项目等情况。不应为验收停止用户正在运行的项目。

实现参数已核对 [Vite 官方 CLI 文档](https://vite.dev/guide/cli) 和 [npm run 官方文档](https://docs.npmjs.com/cli/v11/commands/npm-run/)。npm 的前置/后置脚本不会接收转发参数，因此首版不将这些入口视作单服务适配。
