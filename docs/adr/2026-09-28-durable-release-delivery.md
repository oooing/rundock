# ADR：持久产物与 GitHub 交付

状态：已实现。

## 背景

现有产物记录只保存构建目录的路径和哈希；候选对象在内存中。重启、候选替换或继续开发会使重试失效。
发布命令也无法可靠判断请求响应丢失后远端是否已经完成。

## 决策

构建完成后把文件复制到用户数据目录中的任务专属产物库，核验后原子封存。
发布以封存清单为输入，按版本组协调全部目标，只有完整校验后才公开草稿。
外部交付使用确定性任务标记与远端事实核对，不宣称网络调用恰好执行一次。
现有 Git 和候选流程保留；上传阶段从候选生命周期中分离。
GitHub 是首个且唯一内置目的地，不引入插件注册表。凭证经本机认证提供者使用，不进入项目配置。

## 影响与边界

占用额外磁盘，未完成交付必须保留产物。用户显式删除后任务不能恢复。
本机文件锁负责进程互斥；外部同 Tag 竞争以远端冲突阻断，不提供跨机器排他保证。
验证命令是用户信任的项目代码，不是任意代码沙箱；发布凭证不能注入构建命令。
项目工作流迁移及真实服务验收必须单独记录，模拟验收不能代替真实发布证据。

追踪：docs/plans/2026-09-28-build-delivery.md。

## 工作流及凭证决策

本地交付和云端构建共享 Tag 命名、冻结提交和下载仓库。云端改为明确的 workflow_dispatch，
输入包含 Tag、提交、任务 ID 和目标 ID；响应丢失只查询原任务，明确 4xx 拒绝才允许再次调用。
本地与远端默认分支的工作流内容必须一致，哈希统一 LF，避免 Windows 换行造成误阻断。
第一版保守阻断 Tag/release/create/workflow_run 等可能连锁触发的入口；清理临时 Actions
产物改为每天和手动运行。普通明确分支 CI 可以保留。

GitHub CLI 仅使用系统密钥环中的当前账号，并核对配置中的账号名称。构建环境不继承 GitHub
token；签名由项目显式验证命令处理。本机项目脚本仍属于用户信任的代码，不是安全沙箱。
同一用户数据目录支持跨进程互斥；不同数据目录或其他机器由远端冲突检查兜底，不承诺排他锁。

## 验收后的修正

产物验证脚本本身也必须保持冻结源码不变；验证后再次检查候选内容，再允许封存和发布。
云端恢复不依赖已丢失的候选目录。界面依据冻结任务的交接状态显示结果，不能拿当前项目配置
推断历史任务是否启动过云端构建。
