# 发布检查：可靠性优先

## 问题与取舍

局部源码备份被默认选入后，内置依赖推断把备份缺少的配套文件当成发布错误。这不是实际项目构建失败。固定规则只能复现同样的判断，不能模拟每个语言、构建工具和项目的模块解析。

因此取消内置依赖推断的发布阻断能力。保留引用参考，默认折叠，不要求用户补齐猜测的文件。移除基于正则的 Python 依赖推断，避免把注释和字符串中的示例当成真实导入。项目配置的必需检查和实际构建继续决定代码能否发布。

## 保留的阻断条件

- 所选文件不能读取；主动选择的删除不属于读取错误。
- 敏感内容需要处理。检查包含保存副本的历史内容，不只扫描本次改动；人工例外仍与具体内容绑定。
- 文件用途尚未确认，或代码、版本、配置在检查后发生变化。
- 项目必需检查失败、超时、未执行，或被取消。
- 发布过程中的真实构建、产物校验、签名和版本冲突失败。

通过内置检查不表示构建或测试已经通过。项目未配置检查命令时，也不能宣称做过项目测试。保存代码与正式发布仍使用各自的约束，显式关闭检查仍记录为跳过。

## 文件选择

项目配置和已确认的人工选择优先。已跟踪文件继续按原有规则处理，不按目录排除历史代码。未跟踪的根目录 artifacts/、outputs/、reports/ 默认仅留本机；src/artifacts/、artifacts-old/ 等不匹配。需要共享时可以明确纳入。

不修改其他项目的 .gitignore，不删除备份，不自动复制未选文件或敏感文件。

## 命令执行与报错

不再用 RunDock 自身的 PATH 查询结果提前否决项目命令。系统 shell 在实际检查目录执行配置的命令，允许项目本地脚本和备用命令。只有实际执行返回工具缺失时才诊断工具问题。

命令无法启动显示“无法检查”；项目检查返回失败显示退出码并提供执行日志。日志继续脱敏，单条日志上限 64 KiB，超时和取消继续终止进程树。Windows 原生命令输出按系统 OEM 编码转换，UTF-8 行保持原样，避免中文报错乱码。

界面将不可确定的引用放在“引用参考（不影响发布）”，明确以项目检查和构建为准。旧后端的阻断结果仍可定位引用方并提供处理操作，不将历史结果擅自改成通过。

## 验收边界

回归覆盖局部备份、生成文件、TypeScript 后缀转换、被覆盖的 require、Python 注释与字符串、资源修饰符、读取失败、主动删除、目录边界及人工规则。实际项目只读样本探针验证备份分类；临时 Git 仓库验证项目必需检查失败仍阻断。

浏览器隔离验收使用真实 Vue 组件，验证引用提醒不会显示为错误或要求重新检查，以及旧结果定位、工具缺失、项目失败的提示。完整发布模块回归另覆盖检查结果绑定、敏感内容、取消、上传恢复和版本冲突。测试不向 GitHub 发布，也不操作用户项目。

## 2026-10-13 敏感内容确认的增量处理

原流程在用户确认一条测试数据后调用完整 inspectCandidate，重新保存配置、预读取项目并创建全部候选文件，导致一条确认也等待约两分钟。现在增加 release/candidate/review：确认必须与候选内的文件及发现指纹匹配，源码、配置和候选字节绑定仍需有效；仅更新确认权限，保留候选 ID、工作目录和树哈希。已完成的项目检查复用，未完成或失败的检查才执行。确认不自动发布。

前端只有明确的确认操作、且除敏感例外外的请求完全未变，才使用此入口。文件选择或计划变化仍创建新候选；过期、取消、错误和延迟响应不会静默放行或覆盖新状态。旧后台重启前的候选无法复用，需重新建立一次初始检查。

## 2026-10-13 发布窗口读取性能

当前 ingLocalPlay 有 2481 项改动。窗口的配置和历史请求分别约 0.18、0.12 秒；本地 preflight 首次观测到 22.40 秒，重复读取约 4 秒。前端三个请求已并行，主要等待本地仓库信息和文件指纹，不涉及 GitHub 网络访问。旧实现分别计算仓库状态与文件分类的内容指纹，普通文件被完整读取两次；Git 状态操作标记逐个查询，发布配置也重复读取。

改为每次请求建立一个全新内容快照，同一请求的仓库状态和文件分类共享 SHA-256。最多四个工作线程分块读取，限制大文件内存占用；分类仍检查目录边界和符号链接，不使用跨请求的文件大小/时间戳缓存。Git 操作标记合并查询，旧版 Git 保留逐项回退；同一请求只读取一次发布配置。窗口原有 profileReady、loadRevision 与销毁保护保持原样。
