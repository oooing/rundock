# 静默安装与新版生效分开

## 用户约定

默认更新不打断项目和调试。下载并核验安装包后，在后台静默安装文件；原 RunDock、后台和项目继续运行。完整退出并重新启动后，整个新版才生效。关闭到托盘、只退出窗口或重新打开窗口不等于后台已更新。

用户选择“立即生效”时，先展示本后台将停止的项目，明确说明正常退出超时会结束该项目进程，须先保存工作，调试会话不会保留。确认后才停止项目、切换后台，并尝试重新启动原先运行的项目。仅监测的外部项目不在停止范围。确认模式先请求正常退出，最长等待 15 秒，然后只结束本次启动的独立 Windows Job Object；无法核对托管归属或仍有进程存活时取消切换。不会按端口或程序名结束进程。静默安装和未确认的退出流程不启用强制收尾。恢复失败列出项目和原因，不显示全部完成。

## 状态与边界

- `staging`：安装器仍在执行或结果尚未确认。可以关闭窗口；不能再次安装或立即生效。
- `staged`：新版文件已安装，当前后台可能仍为旧版。
- `restoring`：已持久化需要恢复的项目，逐个确认启动结果。
- `finished`：本次事务结束；失败原因和未恢复列表保留，可重试。

安装器等待有时限。超时不强杀安装器，通过 PID 和进程创建时间核对实际状态；身份记录缺失或损坏不能视为安装已完成。同一会话可使用内存中的进程身份，跨重启无法核实时保持阻断并明确说明原因。保留项目、仅退出窗口不依赖恢复记录或后台健康。

EXE 使用 `/S /UPDATE /P` 原位安装，不调用卸载器。文件替换有独占锁、原子日志、原文件校验和异常回滚，两个主程序通过 PE 校验后才提交。正在使用的旧映像暂时保留，后续安装清理可删除的旧映像。

本轮不停项目安装只支持既有 NSIS/EXE 安装。MSI 和跨格式迁移不自动执行，应完整退出后手动安装，不能承诺不中断。

## 验收边界

- 隔离真实后台及 HTTP 项目验证安装不换进程、停止后切换后台、恢复项目、拒绝停止和重复恢复。
- 实际安装版验证安装文件版本与哈希，原后台实例、项目 PID/runId 和 HTTP 连通性保持一致。
- 不将隔离项目的停止/恢复通过，表述为所有用户项目都能无感接续；自动重新启动不能恢复内存或调试现场。
- 本轮仅本地打包安装，不向 GitHub 发布。
