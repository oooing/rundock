# GitHub 连接失败与发布恢复

## 本次故障

ingLocalPlay 记录 `20261013T083908-9ca36e9db98f` 在提交、构建之前读取 GitHub 时失败。它没有提交 SHA、构建产物或已执行的构建目标。旧实现把构建前和构建后的连接检查都存成 `delivery_preflight`，进度条因此错误地将构建显示为完成。

只读复现中，账号和仓库查询通过，读取 `container-image.yml` 时约 10 秒后返回 `github_request_unconfirmed`；整段前置流程约 18.52 秒失败。随后单独读取和完整流程均成功。旧 CLI 丢弃 stderr，无法追溯那次传输失败究竟是超时还是连接中断，不据此断言代理端口或权限有问题。

## 修改

- 构建前连接使用独立阶段 `delivery_connecting`，并记录阶段开始/失败。旧记录只有在尚无提交时按构建前失败呈现。
- CLI 有界读取错误输出，仅映射为固定错误分类，绝不将原始输出、令牌或带凭证的 URL 写入日志。
- 区分超时、连接中断、无法连接、DNS、证书错误及 HTTP 错误，保留正在读取的内容类别和处理建议。
- 只有 GET/HEAD 的已识别临时故障和部分 5xx 自动补试一次，共用原 45 秒截止时间；权限、证书、404 和写操作不自动重放。
- 本轮构建前，同一账号/仓库只检查一次；不同账号/仓库仍分别验证。正式上传前的后续核验不受影响。
- 连接失败后返回发布页，若原候选仍有效，则保留文件选择、测试密码确认、更新说明和已通过检查；真正发布时仍检查内容绑定，变更后的候选不能沿用。

## 验证

- Go 回归：错误分类、敏感输出不泄漏、读取有限重试、取消、不重复写操作、不同发布仓库/账号、发布恢复相关测试通过。
- 前端交互及进度回归 29 项通过；TypeScript 检查通过。
- `TestLiveGitHubDeliveryPreflight` 通过真实账号、仓库权限和 5 份远端工作流检查，修复后一次实测约 12.26 秒；仅执行读取，没有提交、构建或发布。
- 开发后台通过安全重启加载；托管的看剧鸭按原配置恢复。前端草稿与相同的 615 个所选文件恢复，测试密码例外仍绑定原内容指纹。

完整安装包构建和正式 GitHub Release 发布不属于本次只读联网验收的结论。网络仍可能不可用；修复保证有限等待、真实进度和可操作的失败恢复，不保证外部服务永不失败。
