# 本地构建临时空间回收

日期：2026-10-13

## 问题与处理

此前主要依靠项目脚本的 `finally` 删除编译目录。进程被强制结束时无法保证执行；检查副本也可能一直保留。现在由 RunDock 独立登记和管理临时目录，项目脚本的清理只作为补充。

| 场景 | 处理方式 |
| --- | --- |
| 开始新的发布检查 | 在复制新文件前释放同项目、同仓库的旧检查副本，避免两份同时占空间 |
| 构建/项目检查命令成功、失败、取消、超时 | 结束子进程树后清理该命令的 TEMP/TMP/TMPDIR |
| 标准发布完成或失败 | 删除检查/构建副本；补传使用已保存、校验过的安装包 |
| 旧式自定义发布命令失败 | 暂留用于重试；闲置一小时后进入回收，扫描间隔五分钟 |
| 检查后一直未发布 | 闲置一小时后回收；再次操作需要重新检查 |
| 后台异常退出 | 系统自动释放登记锁；下一次启动回收，已有其他新后台时也可在五分钟扫描中回收 |
| 文件暂时被占用 | 先清理其余文件，保留登记，五分钟后重试 |

程序未运行、机器关机或文件持续被其他程序占用期间，无法保证立即释放空间。恢复运行且解除占用后继续回收。

## 删除边界

- 只清理 RunDock 登记的临时目录；不按名称通配整个系统临时目录。
- 创建目录前先落盘登记，登记持有系统独占锁；其他后台不能回收仍在使用的目录。
- Windows 清理逐层固定目录身份，不跟随目录链接或 junction，不删除链接指向的外部文件。
- 被占用、超时未删完的目录保留登记，不把失败当作清理成功。
- 不删除源项目、共享 npm/Cargo/Gradle 下载缓存、SDK、数据库、发布日志及已保存的安装包。这些并非本轮临时文件；安装包仍用于下载、核验与断网补传。
- TEMP 是步骤级工作区；项目脚本需要跨步骤使用或交付的文件应写入配置的工作目录/产物路径。

源码复制、依赖安装及编译仍需要工作空间。本次减少重叠副本和遗留占用，没有测得 ingLocalPlay PC/Android 完整构建的新峰值；此前预留 20 GB 的建议是保守预算，不是已测量的最低要求。

## 验证证据

1. `outputs/scratch-final-20261013.jsonl`：正常完成、失败、取消、直接退出、文件锁重试、部分文件清理、跨仓库保护、实际 Windows junction、重复回收、非法登记边界。
2. `outputs/scratch-acceptance-20261013.jsonl`、`outputs/scratch-delivery-20261013/delivery-e2e.json`：实际 Git/SQLite/Node 测试仓库，覆盖两个目标完成、网络断开补传、后台重启后补传、取消、超时、多个后台；GitHub 远端使用测试替身，没有公开发布。安装包仍在，补传没有重新构建。
3. `outputs/scratch-regression-focused-20261013.jsonl`：检查确认、取消、内容变化、项目命令和本地构建相关回归通过。最初整套 publisher 测试在旧取消断言处中断，修正断言后通过针对性回归；未宣称全套 publisher 测试通过。
4. `outputs/scratch-runtime-smoke-20261013.json`：独立后台真实启动，回收异常退出遗留的 8 MiB 文件；无主目录归零、登记归零、无关文件保留、原开发后台实例不变。
5. `outputs/legacy-scratch-cleanup-20261013.json`：逐项验证后清理 299 个早于所有现有后台启动时间的旧检查目录，约 180 MiB。旧候选 `2671241498` 不在删除名单中，重查已不存在，不能据此归因于本次清理。
6. `outputs/scratch-live-activation-20261013.json`：开发后台加载与发布历史、项目恢复验证结果。

本轮没有重新构建或发布实际 ingLocalPlay 安装包。
