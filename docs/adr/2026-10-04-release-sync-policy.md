# 发布同步策略

目标：构建位置与交付目的地独立。默认识别所选 Git 远端；GitHub 项目正式发布时同步所选代码和 Tag，本机构建的安装包交付 GitHub Release。用户可以明确选择仅本机。

配置由每个项目的 release profile 持久保存（`syncPolicy: auto | local`），不依赖浏览器缓存。旧 profile 升级为 auto；过去由构建模式隐式写入的 pushRemote 缓存不代表明确的交付配置。仅构建当前版本仍是无提交、无上传的独立操作。

领域边界：profile 决定下一次操作的默认值，候选检查绑定已解析的推送及目标选项；开始发布后冻结计划，不随 profile 变化。安装包必须具备该目标的交付身份、产物规则及验证配置；缺配置明确阻断自动交付，不静默降级成本地成功。

实现前失败清单：非 GitHub URL 被误识别；无远端意外上传；仅本机选择丢失；本地/云端切换覆盖交付选择；保存失败仍声称已保存；打开面板即创建任务；缺少交付配置误报发布完成；候选与推送选项不一致；远端分支/Tag 冲突被覆盖；上传失败丢失产物或重建；重启后策略丢失；当前版本构建意外推送；项目间配置串用。

滚动升级约束：旧后端会忽略新增字段并返回 HTTP 200。前端必须验证保存响应确实包含本次同步策略，缺失或不一致时明确报错并禁止继续发布，不能误报自动保存成功。该校验在 profile API 边界执行，待所有受支持后端均具备该字段后才可移除。

复用已存在的正常 Git push、候选检查、产物封存、草稿上传与哈希核验以及断点重试，不增加自动提交后台任务，不关闭安全检查，不使用强制推送。对外 profile API 新增可选字段；旧客户端明确传入的 pushRemote 仍作为本次任务参数。

验收：隔离的真实 SQLite/API/Vue 与内置浏览器验证保存/重启/切换/提交计划；现有交付端到端夹具验证构建、真实产物、Git 和数据库，只有 GitHub 网络侧模拟故障。证据应注明边界，不将模拟上传称为真实远端发布。
