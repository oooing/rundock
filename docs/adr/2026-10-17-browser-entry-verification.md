# 网页入口与服务运行状态分离

## 问题

看剧鸭的扩展开发服务和网页开发服务都使用 Vite。旧逻辑根据进程归属、日志、响应特征判断服务类型，再优先打开 frontend 地址。扩展服务虽然可以通过 `/@vite/client` 的就绪检查，但根路径返回 404。外部启动观察器又沿用了历史地址，导致卡片显示运行中，却打开了没有首页的端口。

## 决定

- 服务归属和健康检查继续负责运行状态；网页入口使用独立证据，不改变项目进程或健康判定。
- API 响应增加临时的 `webState`、`webReason`、`webUrl`，不把网页检测结果写回数据库或改写用户设置。
- 检查实际候选页面；正常 HTML 才展示网页链接。JSON、JavaScript、空页面、404、下载响应不作为网页入口。保留已声明或已发现的页面子路径，不猜测私有路由。
- 请求只访问本机，不使用系统代理，不携带登录凭证，不跟随跨端口或远程重定向，不用健康检查地址代替网页。
- 后台验证最长 2 秒、全局最多 4 个并发，重复请求共用结果，缓存 10 秒、最多 1024 项。新运行重新验证；列表读取不等待网络。结果变化通知前端。
- 停止、失败或运行状态未知时，不恢复历史地址作为当前入口。端口存在但网页未确认时显示相应状态。
- 点击时再检查实际地址。服务已退出或页面失效时，返回可读提示，由界面展示，不打开已知错误页面。

## 验证

- Go 回归覆盖 HTML/XHTML、接口响应、扩展脚本、404、503、鉴权失败、空响应、精确子路径、安全重定向、取消、缓存去重、慢启动恢复、新运行失效、未知运行态。
- Vue 卡片验证：真实组件只给验证后的页面生成链接，非网页服务保留运行状态，网页失效后禁用入口。
- 只读真实验证：看剧鸭 3000 → `not_page`；11784 → `available`；RunDock 17656 → `available`。
- 加载开发后台修复前后，看剧鸭 3000 / 11784 的进程保持 52276 / 40888，未重启项目。

## 边界

正常 HTML 响应不代表页面内部所有功能正常；登录依赖、浏览器专用证书、用户业务状态不能由无凭证探针完全验证。不把无法确认的情况伪装成成功，也不通过扫描猜测项目私有路由。安装版需重新构建交付，本次不发布 GitHub。
