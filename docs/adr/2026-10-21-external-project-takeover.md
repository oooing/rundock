# 外部启动项目的接管与重启

## 行为

点击外部运行项目的“重启”只查询方案，不关闭进程。

- 完整启动脚本进程链：验证入口、父子进程创建时间、项目归属、服务端口及关闭权限。
- 原启动器已退出：仅接受直接执行项目内绝对路径脚本的独立 Node/Python 服务，且必须存在对应监听服务。仍存活但无法读取身份的父进程不能当作“已退出”。
- 能接管时：列出将关闭的 PID、可确认的脚本地址、重新启动的命令和目录，再提供“重启并接管”。按卡片保存的配置启动，不复用未经确认的外部命令，也不声称接续原调试会话。
- 不能接管时：返回结构化原因和处理步骤。支持重新检查归属，但检查不会执行重启；外部服务已经停止时，刷新卡片并提示使用“启动”。

外部启动器仍在、多个独立服务、共享程序、跨项目子进程、权限不足或身份缺失均拒绝接管。即使其他项目没有登记到 RunDock，明确执行项目外脚本的子进程也会拦截；全局工具脚本可能因此需要从原启动器手动退出。

## 执行保护

沿用一次性、同源、60 秒有效的确认凭据。确认时重新读取进程与配置；PID、创建时间、可执行文件、入口内容或进程集合变化就拒绝执行。按已验证的原生句柄结束目标，保护其他托管项目、共享控制台及 RunDock 启动链。重新启动前继续检查端口和重新拉起的进程，禁止按端口或程序名批量结束进程。

重启意味着结束旧进程后按保存的配置启动。未保存工作、调试连接和进行中的任务可能中断；不是无感接续。

## 2026-10-21 验收

- 后台定向回归通过，包括独立服务 16 种边界、直接脚本识别 9 种边界，以及原有确认凭据、混合进程树、自重启和发布互斥测试。
- Windows 真实临时服务通过：原启动器退出后，独立 Node 服务从 PID 38652 重启为托管 PID 70632；独立对照服务 PID 22740 持续可访问；重复确认返回 409。测试只操作自建临时服务。
- 真实 Vue 浏览器、模拟 API 的 12 组交互检查通过：拦截原因、重新检查不执行、过期凭据、重复操作、新后台连接、托管项目原重启路径、窄屏与键盘交互。
- 开发后台通过自身受保护接口加载修复。看剧鸭 PID 49784、安装版后台 PID 53052、开发前端 PID 7628 保持原创建时间，看剧鸭页面返回 200。
- 看剧鸭真实只读方案识别为 `detached_worker`，列出 Node 49784 / esbuild 9760，并显示接管后使用 `npm.cmd run dev`。实际当前服务使用独立预览配置，本次没有确认它的重启。
- 17656 真实开发页面验收通过：打开看剧鸭重启窗口，核对进程、命令、提醒和“重启并接管”按钮，然后取消；没有发出 `restart-confirm` 请求。

验收时还发现隔离 UI 测试与开发服务器共享默认 Vite 依赖缓存，导致部分开发模块返回 `504 Outdated Optimize Dep`。应用改用独立的 `node_modules/.vite-rundock` 缓存，开发页面恢复；原前端进程保持不变。
