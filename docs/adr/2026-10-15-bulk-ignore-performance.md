# 批量忽略效率与持久化验收

## 原因与实现

原界面逐个调用忽略接口。每个文件独立读取两次项目状态并更新忽略规则，批量文件越多，重复扫描越多。

改为单次请求提交 `files: [{path, contentFingerprint}]`，保留单文件请求兼容。后台一次读取项目状态、一次读取 Git 跟踪清单、一次批量查询忽略状态。逐项验证路径、内容指纹和跟踪状态后，按适用的 `.gitignore` 合并规则；每份忽略清单只替换一次，最后统一刷新项目状态。界面只应用一次返回结果，不再逐项刷新。

选择“忽略”立即执行，无额外确认。保留原文件，不提交代码，不修改 Git 索引，不取消跟踪既有文件。

## 失败处理

- 全部输入和目标清单先验证，再开始写入。
- 临时文件写完并同步后再次核对目标，避免覆盖期间发生的外部编辑。
- 多份清单不承诺跨文件原子事务；失败时报告完成的清单数和原因，界面保留批次以便重试。
- 重试查询 Git 实际状态，跳过已经生效的规则，避免重复写入。
- 规则已写入但刷新失败时明确区分，不误报操作全部失败。

## 验收

在临时 Git 仓库用 664 个小文件测试，未对用户 localPlay 文件实际执行批量忽略。

| 测量 | 1 个文件 | 664 个文件 |
| --- | --- | --- |
| 第一轮操作耗时 | 1.957 秒 | 2.484 秒 |
| 最终回归操作耗时 | 3.462 秒 | 3.567 秒 |
| 项目扫描次数 | 2 | 2 |
| Git 命令次数 | 26 | 26 |
| 本测试写入的忽略清单数 | 1 | 1 |

数据用于证明不再按文件数重复扫描，不代表真实项目固定耗时。文件体积、目录结构和磁盘速度仍影响指纹核对时间。

- 前端 26 项针对性测试通过，覆盖 664 文件单次请求、失败重试、防重复点击和发布锁定。
- 后台单个/批量忽略回归通过，覆盖嵌套规则、特殊文件名、已跟踪文件、内容变化、并发编辑与幂等重试。
- HTTP 路由真实批量请求、重复请求与边界验证通过。
- Vue/TypeScript 类型检查通过，`git diff --check` 通过。
- 日志：`outputs/acceptance/release-ignore-batch-{scale,final,ui,types}.log`。
