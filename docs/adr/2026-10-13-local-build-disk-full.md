# 本地 PC 构建失败：系统临时目录磁盘已满

## 已核实的原因

- ingLocalPlay 发布记录：`20261013T092430-c10b436ec4f8`。
- 冻结提交：`6c7dd0be007b0eb03f9ed67bcf85de45a165245b`。
- GitHub 连接与发布配置核对通过，桌面前端 Vite 构建通过。
- PC Rust 编译在系统临时目录 `rd-native-…/frontend/src-tauri/target/release` 写入元数据时失败：`磁盘空间不足 (os error 112)`，同时出现 LLVM 的 `no space on device`。
- PC 构建失败后停止后续目标；Android、Web 仍在等待。本次没有进入安装包上传阶段。
- 项目虽在 D 盘，原生构建脚本 `New-NativeBuildDirectory` 使用系统 TEMP，实际编译目录位于 C 盘。

## 现场处理

故障后 C 盘可用约 2.84 GiB。失败的原生构建目录已经由脚本 finally 清理，故故障后测得的剩余空间不代表失败瞬间还有空间。

发现 367 个候选临时目录，逻辑文件大小合计 16.19 GiB。其中九个最大的 RunDock 旧副本创建于 10 月 7—12 日，均早于所有当前运行的 RunDock 后台进程启动时间。核验项目身份、隔离索引、无链接、无进程引用后，仅清理这九个明确的绝对路径。实际释放 14.91 GiB，清理完成时 C 盘可用 17.59 GiB。

保留本次候选 `rundock-candidate-2671241498`、原项目、数据库与发布记录、保存的安装包及其余临时目录。没有修改 ingLocalPlay 源码，没有推送代码或重新发布。

证据位于被忽略的 `outputs/`：

- `inglocalplay-latest-failure-followup-20261013.json`
- `candidate-disk-usage-20261013.json`
- `stale-candidate-cleanup-plan-20261013.json`
- `stale-candidate-cleanup-result-20261013.json`

## 代码修正

1. 目标命令失败时识别磁盘已满、超时、取消；将原因与处理办法写入目标状态和诊断记录，不直接把可能含秘密的任意输出抄入主提示。
2. 构建输出和持久化日志同时保留开头与结尾，避免长编译日志截掉最终错误；内存有上限。
3. 正常关闭后台时清理该服务拥有的闲置候选；保留运行中的检查/构建，不扫描删除其他实例的临时目录。
4. 两个公共测试 fixture 在测试结束时关闭发布服务，避免回归测试继续遗留候选目录。

## 验证与边界

磁盘错误分类、实际目标失败状态持久化、长日志尾部保留、闲置/活动/其他实例候选隔离、原有执行步骤/重试、桌面退出与构建改动防护测试通过。测试使用临时本地仓库，没有远端发布。

空间清理已生效。代码修改已通过测试，本轮没有重启正在运行的开发后台，错误提示和正常退出清理将在下一次加载新后台时生效。旧历史记录仍保留当时的原始错误信息。

本轮没有重新执行完整 PC/Android/Web 构建，因此不把释放空间等同于整次发布已经验收。空间需求取决于项目、并发编译与其他程序用量，没有凭固定阈值承诺构建一定通过。强制终止进程留下的候选不属于本次正常退出清理保证。
