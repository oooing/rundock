# 项目进程归属边界

## 问题

外部运行状态检测沿父进程向上寻找项目路径。RunDock 启动看剧鸭后，
看剧鸭属于 RunDock 的操作系统子进程树，因此其端口被重复算到 RunDock 卡片。
父子关系只能证明启动关系，不能单独证明项目归属。

## 修复

- 运行快照同时携带已登记项目、托管启动根进程的 PID 与创建时间、当前后台 PID。
- 有效的托管启动身份优先，不把项目使用的共享工具误认成工具所在项目。
- 非托管进程采用最近的项目路径证据；嵌套目录选择更具体的项目。
- 向上追溯遇到 RunDock 后台即停止，后台自身的监听端口仍可识别。
- 父子进程创建时间不符、身份缺失或证据冲突时不推定归属。
- 卡片、启动前检查、端口冲突检查使用同一带边界的快照。
- 外部重启计划也使用相同的归属判定；树中有其他项目或归属不明进程时拒绝重启，
  不通过过滤列表后关闭父进程来绕过保护。

## 验收（2026-10-17）

回归覆盖托管子项目、共享工具、外部子项目、嵌套项目目录、PID 复用、
无监听端口的其他项目子进程及重启拒绝边界，相关 recovery/API 测试通过。

`TestLiveProjectRuntimeOwnership` 仅 GET 开发接口、读取 Windows 进程和监听者，
在临时数据库运行修复后的识别与卡片数据生成代码，没有操作真实数据库或启停项目。

- RunDock：仅 17655、17656。
- 看剧鸭：4318、11784、11785。4318 与 11784 属于同一个 Vite 进程，确实归看剧鸭。
- 3000、11784、11785、17655、17656 的五个监听进程身份（PID + 创建时间）均未变化。
- 11784 网页、11785 的 Vite 客户端、17656 网页均返回 HTTP 200。

验收输出：`outputs/acceptance/runtime-ownership-live.txt`、
`outputs/acceptance/runtime-ownership-regression.txt`。

## 生效边界

当前 17655 后台仍为修复前进程。本轮没有重启：它托管着看剧鸭，
现有 Job 与进程句柄生命周期不支持无中断转移；强行退出可能中断项目。
等托管项目停止后安全重启 RunDock 开发后台，`scripts/dev.ps1` 会重新编译源码。
真实进程只读验收通过不代表当前在线后台已加载，也不代表生产安装版已更新。
