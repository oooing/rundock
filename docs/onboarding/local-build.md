# 本地构建

本地构建是“发布”中的构建方式；新项目默认云端，可随时切换。

## 使用

1. 项目卡片点 **发布**，将 **构建方式** 切换为 **本地构建**。
2. 要升级版本：选择构建端和版本，检查通过后确认发布。云端和本地共用版本、提交文件及检查区域。
   “发布到哪里”默认 **GitHub（自动识别）**：识别当前 GitHub 远端后自动推送所选代码及 Tag，本机生成的安装包按目标配置上传到 GitHub Release。
   可改为 **仅保存在本机**；配置按项目自动保存，切换构建方式和重启后仍保留。无 GitHub 远端不会上传，缺少安装包交付配置会提示补齐。
3. 只想生成当前安装包：勾选 **仅构建当前版本**，选目标并点 **开始构建**。不提交、不改版本、不创建 Tag、不上传，未初始化 Git 的项目也可用。
4. 完成后点 **打开产物目录** 或 **下载**。切换构建方式、进入设置或关闭窗口不取消后台任务，最近任务可重新查看。

环境缺失或构建失败时，展开日志查看具体原因，处理后开始新构建。
浏览器下载被 IDM 等下载工具接管时，可用“打开产物目录”直接取文件；不必重新构建。
取消会停止本次进程树，不撤销此前已保存的其他任务产物。
本地构建不影响正在运行的项目，但会使用本机 CPU、内存和磁盘；首次下载依赖需要联网。

## 如果没有可选目标

在“设置”中配置目标的本地 `build` 或 `package` 命令，以及 `artifacts` 或 `artifactRules`。
检查命令负责确认 SDK、依赖、签名等；验证命令确认安装包的版本与内容。
没有单独打包命令不代表不能打包：Android 等目标可以在构建命令内同时生成安装包。
只配置云端工作流的目标不能在此执行，不会自动替换成别的构建方式。

配置沿用 [构建与交付指南](build-delivery.md)，无需另建一份本地配置。
普通构建在独立源码副本中执行，不改原项目或 Git 暂存区；项目命令中的绝对路径和外部工具
仍由项目负责，源码副本不是操作系统安全沙箱。依赖安装应由项目已配置的命令处理。

## 产物与版本发布的区别

| 本地构建 | 发布版本 |
| --- | --- |
| 使用当前源码和版本，保存文件 | 按选项更新版本、提交、创建 Tag、上传或部署 |
| 不要求 Git 或新的代码改动 | 遵守原有 Git 与发布前检查 |
| 失败后开始新构建 | 使用发布流程的恢复/重试 |

产物按实例数据目录、任务和目标分别保存，下载前校验大小与 SHA-256。
临时源码被清理或重启后，已保存文件仍可获取；丢失/被修改的文件会明确显示不可用。
备份时请同时保留数据库和数据目录下的 `releases/local-builds`；不要只复制数据库。

验收脚本：`scripts/acceptance/local-build.mjs`，证据保存在 `outputs/acceptance/local-build-<时间>/`。
当前开发源码的验收不代表旧版桌面安装包已经更新。

## 上传失败

发布记录会保留已验证的安装包与上传进度。点“重试上传”可恢复同一次发布，不再增加版本或重新构建；远程冲突和账号不匹配会明确阻断，不覆盖已有内容。
“仅构建当前版本”明确不提交、不创建 Tag、不上传，不受上述自动同步配置影响。

## 重复验收

先在 `sidecar` 中编译 `go build -o .tmp/local-build-validation.exe ./cmd/launcher-sidecar`。
然后在 `code` 中执行 `node scripts/acceptance/local-build.mjs`。
`RUNDOCK_PLAYWRIGHT_MODULE` 可指向已有 Playwright 模块，`RUNDOCK_BROWSER_CHANNEL=msedge` 使用已安装 Edge；
`RUNDOCK_BROWSER_EXECUTABLE` 可指定已有 Chromium 路径。不下载浏览器。
加 `RUNDOCK_ACCEPTANCE_OPEN_FOLDER=1` 可验证真正打开资源管理器。
脚本使用独立数据库、临时夹具项目和浏览器上下文，输出报告、截图、trace 与下载文件。

真实项目验收另用 `scripts/acceptance/local-build-real.mjs`，显式设置
`RUNDOCK_REAL_LOCAL_PROJECT`（项目根目录）和 `RUNDOCK_REAL_LOCAL_TARGET`（目标 ID）。
这会执行项目配置的真实检查、构建和验证，下载依赖并消耗本机资源，但不提交、上传或安装。
`RUNDOCK_SIDECAR` 可指定本次编译的测试后端，避免误用旧二进制。
