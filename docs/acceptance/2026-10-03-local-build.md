## 修复与边界

- Windows 可能因其他程序读取文件而拒绝移动整目录。改为独占目录中写入、同步、校验，
  再通过数据库事务公开产物；半成品不会显示为可下载。
- 保存和恢复均保持已核验文件句柄直到事务提交，重启只恢复完整产物，不自动重跑命令或伪称成功。
- 配置读取期间禁止更改目标，避免异步结果覆盖选择；无 Git 的旧发布预检查拒绝已收进正常 UI 提示。
- Edge 下载被本机 IDM 接管，实际响应是 `204 Intercepted by the IDM Advanced Integration`，
  完整诊断保存在仓库外的 LocalPlay 本地归档，不将浏览器网络记录公开提交。
  这是已确认的环境兼容边界，未通过放宽 CORS 处理。最终 UI 验收使用已有 Chromium 153；
  下载失败时 App 提示重试或在已保存目录取文件。
- 项目配置的构建命令是可信项目代码，源码副本不是操作系统沙箱；SDK 与依赖仍由项目负责。
- 早先整组旧发布 E2E 曾超时，最后仅单独复验上述多目标场景；不宣称旧发布 20 场景全部重验通过。
  本轮未验证真实 GitHub 发布、桌面安装替换或 Android 设备安装。

## 重复验收

参考 [本地构建说明](../onboarding/local-build.md) 的“重复验收”。
本次使用已有 Playwright 和 Chromium，不安装依赖或浏览器：

```powershell
$env:RUNDOCK_SIDECAR='<本次编译的独立测试后端>'
$env:RUNDOCK_PLAYWRIGHT_MODULE='<已有 Playwright 模块>'
$env:RUNDOCK_BROWSER_EXECUTABLE='<已有 Chromium 可执行文件>'
$env:RUNDOCK_ACCEPTANCE_OPEN_FOLDER='1'
node scripts/acceptance/local-build.mjs
```

脚本自行创建独立端口、数据库、夹具项目和浏览器上下文，最终保存可重复验证的报告与产物。
