# RunDock 临时构建产物清理

只清理 Actions 中的 `release-plan-v*` 和 `launcher-windows-v*`，不删除正式 Release 附件、标签、构建缓存或运行日志。

- 整轮 RunDock release 结束后触发清理。正式发布任务成功时，立即删除该轮临时副本，不等待用户安装。
- 失败、取消或仅手动测试构建：只保留最新一轮有可用产物的记录，发布说明和 Windows 安装包一起保留。
- 所有新上传产物的保留期为 1 天（从上传开始计算）。清理失败时仍由 GitHub 到期回收。
- 进行中的运行不参与清理；删除前复查状态和重试次数。
- 没有生成文件的失败不会产生可恢复安装包。临时文件删除后，依赖它的重试需重新构建；正式 Release 下载不受影响。
- 清理器只运行默认分支代码，不执行触发运行里的代码、不下载其产物。
- 这是 RunDock 自身的规则，不会自动修改它管理的其他项目。
- 新保留期不会修改已有产物的过期时间，旧临时产物会在下一次清理时按同一规则处理。

验证：`node --test scripts/tests/artifact-cleanup.test.mjs` 和 `npm run test:release`。
