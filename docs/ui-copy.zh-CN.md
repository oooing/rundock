# RunDock 界面文案规范

## 写给使用者，不写给实现者

发布与设置模块的固定名称用 2–4 字说清对象或动作；说明最多 40 字。已经清楚的“启动”“停止”“重启”“保存”“取消”保留，不为改而改。

这里的字数约束针对中文固定文案和说明模板。用户的项目名、路径、版本号、命令和原始运行记录保留完整，不硬截断；英文按自然表达翻译。短字段名不能丢掉单位，秒数放在紧邻字段的说明中。

## 四条写法

1. **动作明确**：按钮说“做什么”，不让用户猜“处理”“确定”的后果。删除、停止其他程序、上传等风险紧邻按钮说明。
2. **称呼一致**：同一对象统一叫“项目”；同一动作在按钮、提示和帮助中用相同名称。
3. **主次分明**：名称短，条件与后果放在旁边的说明里；高级检查的字段名和填写说明分开。
4. **结果可信**：生成完成、上传完成、正式发布、服务器更新分别说明；未知不写成成功，重试不承诺修复。

说明示例：

- 在线发布：由 GitHub 生成文件，再发布供人下载。
- 本机发布：这台电脑生成文件，再上传 GitHub 发布。
- 本机生成：文件只留在这台电脑，不会上传。
- 临时换端口：只改这次端口，不停其他程序。原设置保留，下次普通启动仍用原端口。
- 跳过文件：只跳过这次修改，下次仍可能询问。
- 部分异常：项目仍在运行，但部分服务暂不可用。恢复后会自动更新状态。

## 覆盖与维护

发布表单不再显示“本次操作”汇总和底部“关闭”。“发布历史”放在发布按钮左侧；历史列表及记录详情使用左上角箭头返回，标题居中。查看历史不重置当前表单，返回时保留文件选择、版本、更新说明和滚动位置。

发布弹窗按主窗口可用高度固定尺寸：电脑保持原有约 94% 的高度，并留出边缘空隙；窄窗口使用约 97%，手机占满可用高度。切换发布、设置、历史、记录详情，或从加载进入内容时，高度不随内容改变；超出内容在弹窗主体内滚动，标题和底部操作固定。调整主窗口大小时，弹窗跟随可用高度适配。

文件区区分两个阶段：上方明确标为“待保存的改动”，勾选决定本次存入新代码记录的内容。新增、修改等按用途分类，“建议保存”默认选中，“待确认”默认跳过，本地资料和私密信息不默认选入；项目规则或有效的个人选择可改变分类或选择。下方标为“已保存，待上传 GitHub 的代码记录”，展示记录和文件数量；绿色对勾是已保存状态，不能勾选或取消。记录也可能含新增、修改、删除或改名，选择上传时整条发送，无需再次选择。该说明在文件列表收起时也可见。

待确认文件的批量下拉框不再显示旁边的“批量操作”标签，选项简写为“批量保存”“批量跳过”“批量忽略”。右侧信息图标点击展开说明气泡，解释保存代码、本次跳过和以后忽略，只作用于待确认的全部文件；每行不再重复提示跳过含义。气泡支持再次点击、点击外部或 Esc 关闭，滚动或调整窗口时收起；已保存文件不能批量忽略的限制与原确认流程保留。

覆盖导航、项目卡片、添加项目、设置、动画、帮助、关闭与重启、端口占用、更新、发布选项、文件检查、生成与上传进度、结果和错误提示。

通用显示文案集中在 `src/i18n/productCopy.ts`；发布与设置的短名称和说明在 `src/i18n/releaseSettingsCopy.ts` 中优先覆盖。原来的翻译键保持稳定，避免文案修改影响 API 消息匹配或操作逻辑。中文、英文成对维护；未知错误和用户输入不会被关键词批量替换。

`npm run test:i18n` 会验证：发布与设置新增名称 2–4 字、说明不超过 40 字、中英覆盖、插值参数、未知文本原样保留、系统语言和手动语言选择优先级。其他模块的原有名称仍按 2–6 字校验。更改文案后还应运行 `npm run build` 并检查实际界面。

本次只修改显示层，不重启后台、不停止项目，也不发起真实发布。已安装的桌面版需使用包含这些修改的新安装包。

## 原则来源

- [Steve Krug：Don't Make Me Think](https://sensible.com/dont-make-me-think/)：减少用户理解界面所需的思考，采用熟悉、明确的表达。
- [Robin Williams：The Non-Designer’s Design Book](https://www.peachpit.com/store/non-designers-design-book-9780321193858)：借用亲密性、对齐、重复和对比的原则，把名称、说明与操作组织清楚。本次不重做布局。
